# Приложение «Task Manager» — это кроссплатформенный мобильный менеджер задач, разработанный на платформе .NET MAUI с использованием языка разметки XAML.

Целью данной работы было создание главного экрана приложения, который позволяет пользователю добавлять задачи, отмечать их как выполненные и фильтровать список.

# 1. Архитектура проекта (Структура)

В соответствии с требованиями курса проект имеет следующую структуру:

Models: содержит модель данных TaskItem.cs, описывающую сущность задачи (Id, Title, IsCompleted). Реализован интерфейс INotifyPropertyChanged. Дополнительно: в рамках повышенного задания добавлен файл TaskPriority.cs — перечисление приоритетов, а также свойства приоритета и даты создания в модели TaskItem.
Views: здесь находится главный экран приложения MainPage.xaml. Он состоит из двух файлов: .xaml отвечает за визуальную разметку интерфейса, а .xaml.cs — за логику взаимодействия.
# 2. Интерфейс пользователя (XAML-разметка)

Интерфейс построен на основе контейнера <Grid>, что обеспечивает гибкую компоновку элементов при изменении размеров экрана.

Корневой Grid разделён на три строки:
Первая строка (Auto) — заголовок. Содержит два лейбла («Task Manager», «Список задач»). Используется вертикальный стэк для выравнивания текста друг под другом.
Вторая строка (Auto) — форма ввода. В ней расположен горизонтальный грид с полем ввода (Entry), кнопкой добавления и переключателем фильтра. Под ними размещён флажок «Скрыть выполненные».
Третья строка (*) — область прокрутки.* Занимает всё оставшееся место. Здесь расположен элемент <CollectionView> без обёртки в ScrollView, так как он сам предоставляет виртуализацию списка.

Элементы управления:

<Entry> с обработчиком события завершения ввода (ReturnType="Done").
<Button> с обработчиком нажатия.
<Switch> с событием Toggled для фильтрации.
<CheckBox> в шаблоне элемента списка для отметки выполнения.
Дополнительно: выпадающий список <Picker> для выбора приоритета.
# 3. Шаблонизация данных (DataTemplate)

Для отображения каждой задачи используется шаблон элемента внутри <CollectionView.ItemTemplate>. Элемент представляет собой контейнер <Border> с закруглёнными углами, содержащий сетку из трёх колонок:

Цветовая полоса слева, привязанная к свойству PriorityColor.
Флажок проверки.
Блок с названием задачи и дополнительной информацией.

Название задачи оформлено через триггеры <DataTrigger>: если задача выполнена (IsCompleted = true), текст зачёркивается и становится серым. Это реализовано благодаря реализации интерфейса INotifyPropertyChanged в модели.

# 4. Логика работы (Code-behind)

Вся логика сосредоточена в файле MainPage.xaml.cs.

При создании страницы вызывается метод LoadTestData(), который генерирует четыре тестовые задачи, одна из которых уже выполнена.
Метод RefreshList() обновляет источник данных коллекции, применяя фильтр по состоянию переключателя.
Обработчик кнопки OnAddClicked() проверяет пустоту поля ввода, добавляет новую задачу и очищает поле.
Для выпадающего списка Picker задано свойство ItemsSource со списком названий приоритетов.
# 5. Дополнительные возможности

Добавлена дата создания задачи (DateTime CreatedAt), которая выводится в шаблоне элемента.
Добавлены вычисляемые свойства цвета и названия приоритета в модели.
На экране появилась возможность выбрать приоритет новой задачи перед добавлением.


| № | Проверка | Ожидаемый результат | Фактический результат |
|---|---|---|---|
| 1 | Добавить задачу длиной 80–100 символов | Текст переносится, не обрезается | + |
| 2 | Добавить 15–20 задач | Список прокручивается, заголовок и поле ввода остаются на месте | + |
| 3 | Повернуть эмулятор в альбомную ориентацию | Элементы не перекрываются, кнопка видна | + |
| 4 | Нажать **Добавить** при пустом поле | Задача не добавляется | + |
| 5 | Включить **Скрыть выполненные** | Выполненные задачи исчезают | + |

# 7. Что требуется для запуска?

- JetBrains Rider;
- установленным .NET SDK;
- настроенным .NET MAUI workload;
- Android SDK и эмулятором либо физическим Android-устройством.
